Erasechat — Privacy Policy

Last Updated: October 9, 2026
In short: Erasechat does not collect, transmit, sell, or share any user data, on any of the six platforms it supports. All processing happens locally in your browser. The only network calls go directly to the platform you're managing — there is no developer-operated backend server.

Overview

Erasechat helps users bulk-delete their own content on Slack (built in) and five optional platforms connected one at a time from the popup: Reddit, X, Mastodon, Microsoft Teams, and Telegram. This policy describes what data the extension accesses for each platform, how it is used, and how it is stored. Connecting a platform beyond Slack is always an explicit action you take — nothing beyond Slack is ever contacted automatically.

Every credential above — Slack's session token included — is memory-only (chrome.storage.session), cleared the moment the browser closes (or when you disconnect that platform), and never written to disk. Closing the browser does not end a Telegram session on Telegram's side — use Log out for that. A Mastodon token stays valid on your instance until you revoke it there. Only the non-sensitive labels marked chrome.storage.local above persist across a restart, purely so the popup can show you're still connected without asking you to reconnect every time; none of them can authenticate a request on their own.

Mastodon's host permission is requested narrowly for the one instance you typed — never a blanket grant across every Mastodon server. Telegram needs no host permission at all: it talks to Telegram's own MTProto servers over WebSockets.

Delete-progress markers

For the five optional platforms, a small marker — just two numbers, items processed and total — is written to chrome.storage.local while a deletion is actively running, so a tab closed or crashed mid-delete leaves you an honest "previous run was interrupted" notice instead of silence. It never contains message content, clears automatically when a deletion finishes, and cannot resume a delete without you running a fresh scan first.

Whose content can be deleted

By default every platform targets only your own content. Two opt-in modes go further, only where the platform itself allows it:

  • Slack "All Messages" (for workspace admins/owners) can delete other members' messages in the open conversation if your role permits it. Saved presets never switch to it on their own.
  • Telegram with "Only my messages" off shows every message, labelled You / Someone else, and can delete selected messages for everyone where Telegram permits it (e.g. both sides of a private chat, or a group you administer). Only your own messages start selected.

What deletion can and cannot remove

Erasechat uses each platform's normal delete action. It cannot override retention, legal-hold, eDiscovery, or compliance-export settings — Microsoft Teams tenants and enterprise Slack plans in particular may keep server-side copies this tool cannot remove. Copies others already have (notifications, emails, other clients, federated Mastodon servers) are also out of reach.

Data the extension does NOT access, on any platform

  • Message content is generally not stored to disk on any platform. The one exception on Slack: "Only Delete Attachments (preserve text)" persists the edited message's text to local storage for the duration of that operation so it can be restored if the browser interrupts the job; it is deleted when the operation completes or is cancelled.
  • No browsing history, bookmarks, or unrelated cookies — only the specific session/auth data each platform's own login mechanism requires.
  • No personal information beyond what's needed to authenticate as you and show scan results.

How data is used

All data accessed, on every platform, is used exclusively for that platform's own scan/delete functionality: authenticating your requests, previewing what will be deleted before you confirm, and tracking in-progress deletion state. Nothing is aggregated, profiled, or reused beyond the operation you started.

Data storage & sharing

  • Export and import stay on your device. "Export CSV/JSON" builds the file in your browser and saves it through your normal download. Importing a Reddit data export or an X archive reads the files you pick locally; nothing is uploaded, and imported items live only in that dashboard tab's memory.
  • No data is transmitted to external servers. Every call goes directly from your browser to the platform being managed — Slack, reddit.com, x.com, your chosen Mastodon instance, teams.cloud.microsoft / teams.microsoft.com, or Telegram's own MTProto servers.
  • No platform's credential is ever written to disk. Slack's session token, Reddit's modhash, X's CSRF token, Mastodon's access token, the Teams Bearer token, and Telegram's session string all live only in chrome.storage.session (memory-only, cleared on browser close). Only non-sensitive labels — your Reddit/X/Mastodon username, the Mastodon instance URL, the Teams API base URL, and Telegram's api_id/api_hash — persist in chrome.storage.local so you don't have to reconnect every time; none of them can authenticate a request on their own, none ever leaves your device, and none is synced to any account.
  • No analytics, telemetry, tracking, advertising, or data brokers, on any platform. Nothing is shared with any entity other than the platform you're directly operating on, at your own direction.

User control

  • Pause, resume, or cancel any Slack deletion at any time; closing a dashboard tab stops operations for that platform.
  • Connect or disconnect any of the five optional platforms independently from the popup. Disconnecting clears that platform's stored credential and labels and removes the browser permissions it was granted; it never affects the other platforms.
  • On Telegram, Log out in the dashboard also ends the session on Telegram's servers.
  • A paused Slack job that is never resumed or cancelled is discarded automatically after 30 days.
  • Uninstalling the extension clears all stored data across every platform.
  • Deletions require explicit confirmation on every platform, with a stricter "type the exact count" step for large batches (>100 items) instead of a fixed one-word confirmation.

Security

  • Every platform's credential — Slack included — is memory-only (chrome.storage.session) and never persisted to disk; each is sent only to that platform's own API, never anywhere else.
  • The Slack dashboard renders inside a Shadow DOM, isolated from the host page.
  • Message sender origins are validated before processing.
  • User text filters are guarded against regex denial-of-service (ReDoS).
  • Scanned content is always rendered as plain text in every dashboard, never as raw HTML.

Children's privacy

Erasechat is not directed at children under 13 and does not knowingly collect personal information from children.
