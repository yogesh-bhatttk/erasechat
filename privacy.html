Bulk Clean for Slack — Privacy Policy

Last Updated: September 7, 2026
In short: Bulk Clean for Slack does not collect, transmit, sell, or share any user data, on any of the seven platforms it supports. All processing happens locally in your browser. The only network calls go directly to the platform you're managing — there is no developer-operated backend server.

Overview

Bulk Clean for Slack helps users bulk-delete their own content on Slack (built in) and six optional platforms connected one at a time from the popup: Reddit, X, Mastodon, Microsoft Teams, Bluesky, and Telegram. This policy describes what data the extension accesses for each platform, how it is used, and how it is stored. Connecting a platform beyond Slack is always an explicit action you take — nothing beyond Slack is ever contacted automatically.

Data the extension accesses — the six optional platforms

Each of these is only ever contacted after you explicitly connect it from the popup. Scanned post/message text and timestamps are, on every platform, held only in browser memory for the current dashboard tab and cleared when the tab closes or a new scan runs — never written to disk.

Mastodon's host permission is requested narrowly for the one instance you typed — never a blanket grant across every Mastodon server. Telegram needs no host permission at all: it talks to Telegram's own MTProto servers over WebSockets.

Delete-progress markers

For the six optional platforms, a small marker — just two numbers, items processed and total — is written to chrome.storage.local while a deletion is actively running, so a tab closed or crashed mid-delete leaves you an honest "previous run was interrupted" notice instead of silence. It never contains message content, clears automatically when a deletion finishes, and cannot resume a delete without you running a fresh scan first.

Data the extension does NOT access, on any platform

  • Message content is generally not stored to disk on any platform. The one exception on Slack: "Only Delete Attachments (preserve text)" persists the edited message's text to local storage for the duration of that operation so it can be restored if the browser interrupts the job; it is deleted when the operation completes or is cancelled.
  • No browsing history, bookmarks, or unrelated cookies — only the specific session/auth data each platform's own login mechanism requires.
  • No personal information beyond what's needed to authenticate as you and show scan results.

How data is used

All data accessed, on every platform, is used exclusively for that platform's own scan/delete functionality: authenticating your requests, previewing what will be deleted before you confirm, and tracking in-progress deletion state. Nothing is aggregated, profiled, or reused beyond the operation you started.

Data storage & sharing

  • No data is transmitted to external servers. Every call goes directly from your browser to the platform being managed — Slack, reddit.com, x.com, your chosen Mastodon instance, teams.microsoft.com, your account's Bluesky PDS, or Telegram's own MTProto servers.
  • Slack's session token is never written to disk — it lives only in chrome.storage.session (memory-only, cleared on browser close). The other platforms' credentials are stored locally in chrome.storage.local (or, for Bluesky, IndexedDB) so you don't have to reconnect every time — this never leaves your device and is never synced to any account.
  • No analytics, telemetry, tracking, advertising, or data brokers, on any platform. Nothing is shared with any entity other than the platform you're directly operating on, at your own direction.

User control

  • Pause, resume, or cancel any Slack deletion at any time; closing a dashboard tab stops operations for that platform.
  • Connect or disconnect any of the six optional platforms independently — none of them are required to use Slack, and connecting one never affects the others.
  • Uninstalling the extension clears all stored data across every platform.
  • Deletions require explicit confirmation on every platform, with a stricter "type the exact count" step for large batches (>100 items) instead of a fixed one-word confirmation.

Security

  • Slack's session token is memory-only and never persisted to disk; other platforms' tokens stay local to your device and are never sent anywhere but that platform's own API.
  • The Slack dashboard renders inside a Shadow DOM, isolated from the host page.
  • Message sender origins are validated before processing.
  • User text filters are guarded against regex denial-of-service (ReDoS).
  • Scanned content is always rendered as plain text in every dashboard, never as raw HTML.

Children's privacy

Bulk Clean for Slack is not directed at children under 13 and does not knowingly collect personal information from children.
